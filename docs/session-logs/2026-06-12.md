## 1. Feature shipped: automatic min-prominence for θ-2θ peak detection

**Objective.** Eliminate the manual peak-detection tuning step. Previously a user
(Tushar) had to hand-lower the "Min prominence" parameter on every θ-2θ scan to
recover the correct peak set; the goal was an automatic criterion that finds
substrate + film (00l) peaks without tuning.

**Method.** spec → plan → implement, in six TDD tasks, each with an independent
spec-compliance review and a code-quality review, then a whole-feature integration
review. Full test suite run before every commit.

**Approach.** Replaced the old fixed-threshold default (1.5% of intensity range)
with a two-part automatic criterion: (1) a log-domain prominence test — a peak must
rise ≥0.3 decades (~2×) above neighbouring troughs on log₁₀(counts), scale-invariant
across the ~6-decade dynamic range of a θ-2θ scan; and (2) a Poisson significance
guard requiring ≥5σ.

**Key problem found and resolved.** The first implementation passed all synthetic
tests but, reviewed against real data, flooded scan S05 with 647 spurious peaks.
Root cause: our Rigaku exports are counts-per-second (not raw photon counts) with a
baseline ~70% exact zeros; the textbook Poisson guard `σ = √counts` collapsed to a
flat ~5-count threshold so single-photon blips passed. Fix: estimate the per-scan
count quantum *q* (intensity per detected photon, ~4.5–15 cps) and evaluate
significance in photon units as a difference-of-Poissons. After the fix the
over-segmentation cases dropped from 647 / 66 / 69 peaks (S05 / S10 / S06) to
3 / 3 / 2, while genuine strong films were retained.

**Key decision.** Confirmed a conservative sensitivity: auto-detect captures
confident peaks (substrate; strong films ≥~10× local background, e.g. S11) and
treats marginal ~3× background bumps as noise. Consequence: weak-film scans
(S05/S04/S10) return substrate-only — intended behaviour — with the manual override
kept for digging into genuinely weak films.

**Verification.** Full suite 151 passed / 0 failed / 2 incomplete (the 2 are
pre-existing gated tests for validation files absent on this machine). Added 5 gated
real-data regression tests (S04/S05/S06/S10/S11) + a reusable calibration sweep
script. Independent integration review: ready to merge, no critical/important issues.

**Deliverables.** Library: log-domain auto-prominence + unit-aware Poisson guard in
`findPeaks`; `identifyMaterial` and the GUI updated to use it (GUI "Min prom (%)"
defaults to `auto`, numeric entry overrides). Tests + docs (USER_GUIDE,
SCIENTIFIC_ASSUMPTIONS §3.3, FEATURES, DATA_SWEEP). Pushed `a5b6624..266af2d` to
`main` (7 implementation commits + spec/plan).

**Known limitation (logged for follow-up).** The quantum estimator's "≥5%
exact-zero" trigger is a hard threshold; harmless on real scans (57–70% zeros) but
could behave discontinuously near the boundary. Noted in SCIENTIFIC_ASSUMPTIONS §3.3.

## 2. Capability confirmed (built earlier, rediscovered today): material ID from peak positions

Went looking to "tell the material and its properties from peak positions" — turns
out this already exists from an earlier session (material-ID feature, spec
2026-06-09). Recording it here so it's not lost again.

**Entry points.** `xrdc.lattice.identifyMaterial(peaks, lambda, Substrate=...)`, and
the GUI "Identify Material" button on θ-2θ scans. The auto-prominence work above
feeds it directly (better peak positions → better ID).

**Usage.**
```matlab
scan = xrdc.io.readScan(path);
pk   = xrdc.peaks.findPeaks(scan);                 % auto prominence
R    = xrdc.lattice.identifyMaterial(pk, scan.lambda, Substrate="SrTiO3");
R.series      % one row per identified phase
```

**What it reports, per identified phase.**
- Material (`bestMatch`) + ranked candidate list with scores (never a lone guess) +
  ambiguity flags. Database: SrTiO₃, PbTiO₃, PZT, SrRuO₃.
- Out-of-plane lattice parameter `c` ± σ (LSQ fit over all matched (00l) orders).
- Strain state — vs bulk, vs pseudomorphic-on-substrate prediction — and a
  relaxation fraction (0 = fully strained, 1 = fully relaxed).
- Composition — for PZT, a Zr-fraction `x` estimate, with the caveat that (00l)
  alone is strain-confounded (needs in-plane `a` from RSM / asymmetric reflection).
- Substrate confirmation, matched (00l) labels, unassigned peaks, Kβ/W-Lα ghost
  filtering.

Documented in USER_GUIDE §4.6.

**Candidate extensions (not yet built) — to scope if needed.**
1. More materials in `materials.json` (e.g. PtO₂ / TiO₂ from the data dump are not in
   the DB yet).
2. More properties — crystallite size / microstrain from peak *widths*
   (Scherrer / Williamson-Hall), d-spacings, full unit cell, fringe thickness.
3. Non-(00l) / polycrystalline (powder) ID — a different matching algorithm.

## 3. Roadmap research: candidate features to add

Ran a deep-research pass on high-value analysis features to add to the toolkit.
Full report saved to `docs/research/2026-06-12-hrxrd-feature-research.md`. Headline:
the top-priority addition is an **RSM-based strain/composition decomposition** module
(pick asymmetric-RSM peaks → q∥/q⊥ → biaxial strain → relaxed a₀ → Vegard composition),
which directly fixes the (00l)-only limitation surfaced today (PTO-vs-PZT degeneracy,
films compressed below bulk c). Next tier: full Parratt/Abelès XRR fitting and
quantitative RSM analytics (relaxation degree, tilt, mosaic-vs-size). All Stage-1/2
items reuse data the group already collects — no new measurement types.
