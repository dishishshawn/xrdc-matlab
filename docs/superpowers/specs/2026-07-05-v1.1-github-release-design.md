# v1.1 GitHub release + shareable repo — design

**Date:** 2026-07-05
**Owner:** Shawn Agarwal (shawnagarwal0@gmail.com), Paik group
**Status:** Approved design (revised for exe-first delivery), pending implementation plan

## Problem

A lot has shipped since the original hand-off to Tushar (lab assistant, primary
day-to-day user), but there is no clean way to give him — or anyone — the current
version. Two facts drive the design:

- **Tushar does not have MATLAB.** So the deliverable he actually needs is a
  runnable Windows build, not the MATLAB source. The source path still matters
  for group members who do have MATLAB.
- The repo `github.com/dishishshawn/xrdc-matlab` is **already public**, but the
  root has **no README** (bare file-tree landing page), **no LICENSE** (silent
  all-rights-reserved default), and there is **no version string anywhere** in
  the code, so nothing is marked v1.0 / v1.1.

Goal: make the repo self-explanatory so Shawn sends the link, a **no-MATLAB user
downloads a runnable v1.1.0 installer** and is going in minutes, MATLAB users can
still grab the source, and the app itself reports its version.

## Delivery model (exe-first)

The v1.1.0 GitHub Release carries two download paths:

1. **Primary — `XRDCInstaller.exe`** (custom Release asset): a ~3 MB web
   installer produced by `buildStandalone(Embed=true)` (`RuntimeDelivery="web"`).
   The user double-clicks it; it downloads the matching **MATLAB Runtime R2026a**
   at install time (one-time, needs internet) and installs XRDC. No MATLAB
   license required. This is Tushar's path.
2. **Secondary — source zip** (auto-attached by GitHub to every Release): for
   group members with MATLAB R2022b+ (`addpath` + `xrdcApp`).

## Non-goals (out of scope for v1.1)

- **Offline installer** that bundles the Runtime (`Embed=true, Offline=true`,
  ~2–4 GB) — exceeds GitHub's 2 GB per-asset limit; the web installer fetches the
  Runtime at install instead.
- **macOS / Linux builds** — the exe is Windows-only; cross-platform builds would
  need a build on each OS (see `build/buildStandalone.m`).
- **Restructuring** `xrdc-matlab/` up to the repo root — needless path/history
  churn; a root README that links into the subdir is enough.
- **Data-privacy remediation** of the already-public `data/` and `.claude/`
  directories — flagged as a TODO for the owner, not changed here.

## Decisions (locked with owner)

| Decision           | Choice                                                              |
| ------------------ | ------------------------------------------------------------------ |
| Delivery mechanism | The public GitHub repo + a v1.1.0 Release (send the link)          |
| Primary download   | `XRDCInstaller.exe` web installer (`buildStandalone(Embed=true)`), for no-MATLAB users incl. Tushar |
| Secondary download | GitHub's auto-attached source zip, for MATLAB users                |
| Landing page       | New root README with an exe-first "Download & Install" section     |
| Version stamp      | In-app **and** docs: `xrdc.version()` in the app title, referenced in READMEs + release notes |
| License            | **Academic / all-rights-reserved** notice (not an OSI license)     |
| Repo layout        | Keep `xrdc-matlab/` as a subdir; root README links into it         |
| Version number     | `1.1.0` (original taken as the implicit v1.0)                       |

## Components

### 1. In-app version (the only production code change)

- **`xrdc-matlab/+xrdc/version.m`** — public function returning `"1.1.0"` as a
  single source of truth. No inputs; returns a `string` per
  `xrdc-matlab/CLAUDE.md` conventions.
- **`xrdc-matlab/xrdcApp.m`** — the app already sets
  `uifigure('Name', 'XRDC Scan Analyzer', ...)` at `xrdcApp.m:27`; append the
  version via a single `xrdc.version()` call so the GUI title reads
  `XRDC Scan Analyzer v1.1.0`.
- **`xrdc-matlab/tests/testVersion.m`** — `functiontests(localfunctions)`:
  known-answer (`== "1.1.0"`) + semver-format (`^\d+\.\d+\.\d+$`).

Because the installer bakes in source at build time, the installer must be
**rebuilt from the v1.1.0 source** so the shipped app reports v1.1.0 (see §7).

### 2. Root `README.md` (landing page, exe-first)

1. One-line description of what XRDC is.
2. **Download & Install:**
   - **No MATLAB? (recommended — most users, incl. lab members without a
     license):** download `XRDCInstaller.exe` from the latest Release →
     double-click → it fetches the MATLAB Runtime (R2026a, one-time, needs
     internet) → launch XRDC.
   - **Have MATLAB R2022b+?:** download the source zip (or `git clone`) →
     `cd xrdc-matlab` → `addpath(pwd)` → `xrdcApp`.
3. **Requirements** — installer path needs Windows + internet once (for the
   Runtime); source path needs MATLAB R2022b+ (optional toolboxes, fallbacks
   exist — point to the subdir README's toolbox table).
4. Link to `xrdc-matlab/README.md` for full usage, scripts, and API.
5. **Credits & citation** — Schwaigert et al. *J. Vac. Sci. Technol. A* **41**,
   022703 (2023); algorithms originate from Dr. Tassilo Heeg's Delphi XRDC.
6. **License** pointer to root `LICENSE`.

### 3. `LICENSE` (academic notice, repo root)

Custom academic-use terms (GitHub displays but does not auto-classify): © Paik
group, for academic/research use, contact Shawn for use beyond that, cite
Schwaigert et al. *JVST A* **41**, 022703 (2023), algorithms originate from Dr.
Tassilo Heeg's Delphi XRDC (FZJ/ISG1-IT). Referenced from both READMEs.

### 4. `CHANGELOG.md` (repo root)

A `v1.1.0` section; the same prose becomes the GitHub Release body. No prior tag
exists, so v1.1.0 is the first tagged release and the notes summarize current
capabilities. **Draft bullets (owner trims/confirms at spec review):**

- **XRR slab-model fitting** — Parratt reflectivity with Névot–Croce roughness;
  seeded multi-start fit of thickness / density / roughness with parameter SEs.
- **RSM strain & composition** — `analyzeStrainRSM`: auto-find RSM peaks →
  in-plane / out-of-plane lattice parameters → biaxial strain → relaxed `a0` →
  PZT composition (geometry validated on real TiO₂ data; strain/composition
  synthetic-only this iteration).
- **Material identification** — `identifyMaterial` from lattice parameters
  (documented PTO-vs-PZT (00l) ranking caveat remains).
- **Automatic peak prominence** — data-driven minimum-prominence selection.
- **Expanded I/O and materials** — Rigaku SmartLab Studio II `.hgx` reading;
  added materials (LAO, TiO₂, WO₃) with formula + bulk density.
- **Distribution** — first tagged release; runnable Windows installer for
  no-MATLAB users, plus source for MATLAB users.

Keep the material-ID and synthetic-only caveats visible; do not overstate.

### 7. Build + release — owner-gated (MATLAB unavailable in this environment)

This environment cannot run MATLAB, build the installer, or runtime-verify it —
those are **owner actions on the lab machine**, and they gate the Release. What
can be done here now: all repo/code/doc changes (§1–6) and their local commits;
preparing the tag and release notes.

Sequence (owner-run steps marked ⚙):

1. Land §1–6 as local commits.
2. ⚙ Owner runs `runtests` on lab MATLAB — must be green.
3. ⚙ Owner rebuilds the installer from v1.1.0 source:
   `addpath build; buildStandalone(Embed=true)` →
   `build/standalone/installer/XRDCInstaller.exe`.
4. ⚙ Owner runtime-verifies `XRDCInstaller.exe` on a clean no-MATLAB machine
   (installs, launches, smoke-test per Phase A of the checklist).
5. Push `main`; create annotated tag `v1.1.0`; create the GitHub Release
   (title `v1.1.0`, body = CHANGELOG notes). Source zips auto-attach.
6. Upload the asset: `gh release upload v1.1.0 XRDCInstaller.exe` from whichever
   machine holds the built installer (owner, if it stays on the lab box).

Push, tag, Release, and asset upload are outward-facing and run only on explicit
owner go-ahead.

## Data flow

`xrdc.version()` → consumed by (a) `xrdcApp.m` title, (b) `testVersion.m`
assertion, (c) baked into the installer at build time, (d) referenced by string
in READMEs / CHANGELOG / Release. Single source of truth.

## Testing & verification

- New unit test `testVersion.m` (known-answer + format).
- Full `runtests` **green on lab MATLAB** before release — owner-run.
- Installer **runtime-verified on a clean no-MATLAB machine** before release —
  owner-run.
- Doc changes verified by inspection (rendered landing README, working links,
  Release page shows `XRDCInstaller.exe` + source zips).

## Acceptance criteria

1. `xrdc.version()` returns `"1.1.0"`, covered by `testVersion.m`, and the app
   title shows the version.
2. Root `README.md` renders as the landing page with an **exe-first** Download &
   Install section (installer for no-MATLAB users; source for MATLAB users).
3. Root `LICENSE` present (academic notice); both READMEs point to it.
4. `CHANGELOG.md` has an owner-approved `v1.1.0` section.
5. `RELEASE_CHECKLIST.md` Phase B corrected and the GitHub-release path (incl.
   installer rebuild + runtime-verify) documented.
6. `docs/FEATURES.md` reconciled and the three TODOs logged.
7. On owner go-ahead (green `runtests` + rebuilt, runtime-verified installer):
   `main` pushed, `v1.1.0` tagged, Release published with the notes,
   `XRDCInstaller.exe`, and auto source zips.
