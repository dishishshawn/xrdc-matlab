# v1.1 GitHub release + shareable repo — design

**Date:** 2026-07-05
**Owner:** Shawn Agarwal (shawnagarwal0@gmail.com), Paik group
**Status:** Approved design, pending implementation plan

## Problem

A lot has shipped since the original hand-off to Tushar (lab assistant, direct
user with MATLAB access), but there is no clean way to give him — or anyone —
the current version. Today:

- The repo `github.com/dishishshawn/xrdc-matlab` is **already public**, but the
  root has **no README** (the landing page is a bare file tree) and **no
  LICENSE** (silent all-rights-reserved default).
- Install/usage docs live one level down in `xrdc-matlab/README.md`; a newcomer
  landing on the repo sees no "how do I download / install this" guidance.
- There is **no version string anywhere** in the code, so nothing is marked as
  "v1.0" or "v1.1".

Goal: make the repo self-explanatory so Shawn sends Tushar the link, Tushar sees
a clear landing page, downloads a versioned **v1.1.0**, and installs in MATLAB —
and the app itself reports its version.

## Non-goals (out of scope for v1.1)

- Building the standalone `XRDC.exe` — MATLAB Compiler is not installed on the
  build machine (per `build/RELEASE_CHECKLIST.md`), and the compile cannot be
  run from this environment. Logged as a TODO instead.
- Restructuring the repo to promote `xrdc-matlab/` to the repo root — rejected
  as needless path/history churn that would also break the outer
  `docs/` + `data/` + `validation/` layout.
- Remediating data privacy of the already-public `data/` and `.claude/`
  directories — flagged as a TODO for the owner to decide, not changed here.

## Decisions (locked with owner)

| Decision            | Choice                                                            |
| ------------------- | ---------------------------------------------------------------- |
| Delivery mechanism  | The public GitHub repo itself (send the link)                    |
| Download + v1.1     | Tagged **v1.1.0** git tag + GitHub Release, plus a root README "Download & Install" section pointing at the Releases page |
| Version stamp       | In-app **and** docs: `xrdc.version()` surfaced in the app title, referenced in READMEs + release notes |
| License             | **Academic / all-rights-reserved** notice (not an OSI license)   |
| Repo layout         | Keep `xrdc-matlab/` as a subdir; add a root README that links into it |
| Version number      | `1.1.0` ("v1.1 of the original", original taken as the implicit v1.0) |

## Components

### 1. In-app version (the only production code change)

- **`xrdc-matlab/+xrdc/version.m`** — public function returning the version
  string `"1.1.0"` as a single source of truth. No inputs. Follows
  `xrdc-matlab/CLAUDE.md` conventions (returns a `string`).
- **`xrdc-matlab/xrdcApp.m`** — the app window title incorporates
  `xrdc.version()`. The app already sets `uifigure('Name', 'XRDC Scan
  Analyzer', ...)` at `xrdcApp.m:27`; the version is appended via a single
  `xrdc.version()` call so the running GUI shows `XRDC Scan Analyzer v1.1.0`.
- **`xrdc-matlab/tests/testVersion.m`** — `matlab.unittest` via
  `functiontests(localfunctions)`, per project convention:
  - known-answer: `xrdc.version()` equals `"1.1.0"`;
  - format: matches semantic-version pattern `^\d+\.\d+\.\d+$`.

### 2. Root `README.md` (landing page)

Concise, oriented at a newcomer; deep detail stays in `xrdc-matlab/README.md`.
Sections:

1. One-line description of what XRDC is (mirror the subdir README's opener).
2. **Download & Install** — three paths, Releases first:
   - **Recommended:** the Releases page → download the **v1.1.0** source zip.
   - `git clone https://github.com/dishishshawn/xrdc-matlab.git`.
   - **Code → Download ZIP** for the latest `main`.
   Then the MATLAB step: `cd xrdc-matlab` → `addpath(pwd)` → `runtests`
   (optional) → `xrdcApp`.
3. **Requirements** — MATLAB R2022b+; optional toolboxes with a note that every
   path has a pure-MATLAB fallback (point to the subdir README's toolbox table).
4. Link to `xrdc-matlab/README.md` for full usage, scripts, and API.
5. **Credits & citation** — Schwaigert et al. *J. Vac. Sci. Technol. A* **41**,
   022703 (2023); algorithms originate from Dr. Tassilo Heeg's Delphi XRDC.
6. **License** pointer to the root `LICENSE`.

### 4. `CHANGELOG.md` (repo root)

A `v1.1.0` section; the same prose becomes the GitHub Release body. No prior
release tag exists to diff against, so v1.1.0 is treated as the first tagged
release and the notes summarize current capabilities added since the original
hand-off. **Draft bullets (owner trims/confirms at spec review):**

- **XRR slab-model fitting** — Parratt reflectivity with Névot–Croce roughness,
  seeded multi-start fit of thickness / density / roughness with parameter SEs.
- **RSM strain & composition** — `analyzeStrainRSM`: auto-find RSM peaks →
  in-plane / out-of-plane lattice parameters → biaxial strain → relaxed `a0` →
  PZT composition (geometry validated on real TiO2 data; strain/composition
  validated on synthetic data).
- **Material identification** — `identifyMaterial` from lattice parameters
  (a documented PTO-vs-PZT (00l) ranking caveat remains).
- **Automatic peak prominence** — data-driven minimum-prominence selection for
  peak detection (conservative default).
- **Expanded I/O and materials** — Rigaku SmartLab Studio II `.hgx` reading;
  additional materials (LAO, TiO2, WO3) with formula + bulk density.

Honesty note: keep the material-ID caveat visible; do not overstate synthetic-
only validation.

### 5. Update `xrdc-matlab/build/RELEASE_CHECKLIST.md`

Add a source / GitHub-release path alongside the existing exe path:

  CHANGELOG notes.
- List the version-string locations to keep in sync: `+xrdc/version.m` (source
  of truth), the app title, and any README references.

### 6. TODOs logged (to `xrdc-matlab/docs/FEATURES.md` wanted-list)

### 7. Git / GitHub actions — gated on owner approval

Local commits for all of the above (docs + the version code). Then, **only after
the owner confirms `runtests` is green on lab MATLAB** (Phase A of the release
checklist; this environment cannot run MATLAB):

- push `main` to `origin`;
- create annotated tag `v1.1.0`;
- create the GitHub Release (title `v1.1.0`, body = CHANGELOG notes; GitHub
  auto-attaches the source zip).

Push, tag, and Release are outward-facing and are executed only on explicit
owner go-ahead (or by the owner directly).

## Data flow

`xrdc.version()` → consumed by (a) `xrdcApp.m` title, (b) `testVersion.m`
assertion, (c) referenced by string in READMEs / CHANGELOG / Release. Single
source of truth; bumping one function updates the app.

## Testing & verification

- New unit test `testVersion.m` (known-answer + format).
- Full `runtests` suite must be **green on lab MATLAB** before the release is
  cut — owner-run, since MATLAB is unavailable in the authoring environment.
- Doc changes verified by inspection (rendered README landing, working relative
  links, Release page shows the v1.1.0 zip).

## Acceptance criteria

1. `xrdc.version()` exists, returns `"1.1.0"`, is covered by `testVersion.m`, and
   the app title shows the version.
2. Root `README.md` renders as the repo landing page with a working Download &
   Install section (Releases-first).
3. Root `LICENSE` present with the academic notice; both READMEs point to it.
4. `CHANGELOG.md` has an owner-approved `v1.1.0` section.
5. `RELEASE_CHECKLIST.md` documents the GitHub-release path.
6. The three TODOs are recorded in `docs/FEATURES.md`.
7. On owner go-ahead: `main` pushed, `v1.1.0` tag created, GitHub Release
   published with the notes and downloadable zip.
